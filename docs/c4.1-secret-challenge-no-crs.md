## Decision boundary

This successor excludes common/structured reference strings. It may reuse the
existing verifier-specific base-OT/VOLE/PCG preprocessing and the random-oracle
model already required by Fiat--Shamir. Such private correlated preprocessing
is not a public CRS, but every response-local item remains one-time and must be
burned on abort.

There are two distinct candidates:

1. `C41SC1`, the simple interactive baseline: after the provider fixes the
   registered bridge frontier, the verifier sends one fresh unpredictable
   private `Fp2` challenge. The provider then performs the typed fold and
   degree-12 close. The verifier materializes setup-fixed typed keys before the
   response, then folds them against response-derived descriptors online.
2. `C41NISC1`, the round-free research candidate: during private preprocessing
   the verifier sends a computationally hiding encoding of the same challenge
   packet. After fixing the commitment frontier, the provider evaluates the
   challenge-dependent post-commitment function without learning the packet and
   sends one online message.

`C41NISC1` is preprocess-then-one-message secure computation, not an ordinary
plain-model NIZK and not Fiat--Shamir applied to private verifier coins.

## Active C41SC1 implementation contract

The exact commitment frontier is the point in
`C41ProverResponseState::finish` after all registered response cells, all 640
canonical bridge corrections and all bridge descriptors have been appended,
and immediately before the scalar-power batching challenge. No later prover
move has been appended. The one private message is a uniformly sampled
canonical `Fp2` value `beta` sent verifier-to-provider. Its request binds the
complete C41FS1 public context, the canonical frontier digest, the public-coin
challenge census and the transcript byte census. The response binds the exact
request digest. Both are strict, versioned, create-new artifacts.

Every earlier sequential GKR/PCS challenge remains C41FS1, so no future coin is
revealed early. The private `beta` is appended canonically to the transcript;
all later public coins are C41FS1-derived from a state containing it. Exactly
one private challenge is required and duplicate, missing, malformed,
wrong-frontier or wrong-context releases fail closed.

The verifier key factorization is deliberately simple:

```text
setup/local:     expand compact typed seeds once into a_keys, b_keys
provider/online: q[cell] = sum_j beta^(j+1) descriptor_j[cell]
verifier/online: Kq = sum_cell q[cell] * (a_key[cell], b_key[cell])
```

The materialized lot is a separate verifier-secret setup artifact, not proof
or setup traffic. It is expected to contain `2 * 3,110,400` `Fp2` keys, or
`99,532,800 B` before framing. The existing compact verifier bundle remains
unchanged. The provider uses the existing resident CUDA lot. To remove the
known full-size Rayon scratch multiplication, the provider builds one dense
query buffer by direct sparse scatter before the existing GPU fold; this is a

One issuer command samples from OS entropy and durably burns the request before

## Fiat--Shamir composition

Fiat--Shamir remains applicable to public-coin challenges outside the private
packet. In `C41SC1`, both parties append the canonical private packet after the
commitment frontier and derive every later public challenge from the transcript
containing it. In `C41NISC1`, the public transcript instead binds the one-time
preprocessing identifier and encoding digest; the secure computation consumes
the associated private packet.

The private packet itself is not replaced by Fiat--Shamir. Its statistical
soundness term must be composed with the random-oracle terms, one-time-state
security and the existing conditional XOR4-MAJ7 assumption. Both total
soundness and weight privacy must remain above 78 bits.

For the rejected *offline-prefolded* variant, the packet would have to contain
every coin that determines the typed query, not only the final scalar-power
bridge challenge `beta`. The current query is

```text
q[cell] = sum_j beta^(j+1) * descriptor_j[cell],
```

and each `descriptor_j` includes GKR/PCS evaluation points derived after prior
prover moves. If those points remain response-derived Fiat--Shamir values, the
verifier cannot precompute the final folded key before seeing the response.
Active C41SC1 does not claim that precomputation: it materializes setup-fixed
keys and performs the descriptor fold online after replaying the response.

## Why an offline clear challenge is unsound

Sending the packet in clear before the commitment frontier lets a malicious
provider choose its commitments as a function of the challenge. A commitment
to the packet still needs an online opening. A fixed public pool permits
commitment grinding and would need exponential size to retain the current
soundness. A verifier PRF or VRF either leaves the challenge unavailable to the
provider or requires an online evaluation/release. A randomness beacon, VDF or
TEE merely replaces the client round with a new online dependency or trust
assumption.

Without interaction, CRS or trusted hardware, the provider must therefore
compute the challenge-dependent response on a hidden input. Silent NISC gives
this syntax: the receiver masks its input during preprocessing and the sender
later returns the function output in one message. It does not make the function
free.

## C4.1-specific obstruction

The real proof has `640` live bridge corrections, but hiding only their final
`beta` powers is insufficient. The verifier must authenticate

```text
K_q = sum_cell q[cell] * k[cell]
```

against setup-fixed typed keys. The public descriptors are response-dependent,
while the compact seeds expand to `3,110,400` cells. A provider-supplied value
for `K_q` has no setup-fixed reference and would make the MAC check vacuous.

A generic NISC must securely evaluate seed expansion plus the query fold, or
must securely run all post-commitment openings under a packet that also fixes
the descriptor points. Garbled-circuit and generic OT reductions cost at least
linearly in that function. The existing literature provides no construction
that simultaneously establishes:

- a few-KB retained verifier state;
- no response-critical seed expansion on the client;
- less than the current `2,168,980-B` proof headroom;
- no new CRS or trusted hardware;
- no material prover regression; and
- the inherited soundness, weight-ZK, setup and device-memory gates.

## Required analytic screen before implementation

No protocol code is admitted until a design supplies all of the following:

1. the exact commitment frontier and complete private challenge census;
2. an exact factorization of `K_q` showing which work is offline, provider
   online and verifier online;
3. a malicious-secure no-CRS realization from the existing private
   OT/VOLE/PCG setup, including selective-failure and abort leakage;
4. exact online proof bytes, setup traffic, provider state and verifier state;
5. a work count parameterized by the measured bridge sparse-entry census;
6. one-time burn and multi-response security; and
7. a complete soundness/weight-privacy composition above 78 bits.

The prover diagnostics already expose bridge count and sparse entries. Those
counters are the first empirical input to a specialized NISC screen; they do
not authorize a pod run.

Absent such a factorization, `C41SC1` is the only practical candidate: it pays
one verifier-to-provider message after commitment, retains pre-folded verifier
keys, and keeps Fiat--Shamir for the remaining public challenges.

## Completed screen: FS plus direct chosen-input authentication

Run `python3 docs/check_c41_nisc_budget.py` to reproduce every numerical bound
below. This is an analytic `credit:false` screen: no proof was produced, no
Rust or Lean command ran, and no pod was contacted.

The useful FS split is more aggressive than hiding the final query. Replace
the typed Packed16 layer itself with direct chosen-input authentication:

```text
preprocessing: V publishes a verifier-specific malicious CI-VOLE key for Delta
proof prefix:  P appends a hiding digest of canonical x_auth
later coins:   every GKR/PCS/bridge coin is public C41FS1
outputs:       P gets m[i], V gets k[i], m[i] = k[i] + x_auth[i] * Delta
verification:  both sides fold those ordinary shares at the existing openings
```

`x_auth` is the canonical concatenation of the 27 registered matrices: K and V
for 12 layers plus three group exits, totalling `3,110,400` base-field cells.
Its digest and the one-time response identifier are appended after the fixed
C41FS1 context and before the first `challenge_fp2`. Therefore the complete
private challenge census is exactly zero. Sequential prover moves remain bound
by the existing public Fiat--Shamir transcript; no future challenge is revealed
early.

If malicious CI-VOLE extracts and authenticates that one vector, the current
`a/b` seeds, Packed16 `d/e`, 640 bridge corrections and degree-12 typed close
are unnecessary. The provider folds `m`; the verifier folds `k`. This is the
only screened factorization that can repair prover time rather than add a
second large computation to the failed C4.1 path.

The setup certificate must also prove that the CI-VOLE key uses the same hidden
`Delta` as the existing ordinary VOLE/PCG connection. Honest equality is not
enough: without a joint hidden-key relation, a malicious verifier can put the
new and old authenticated values in different MAC spaces. No reviewed LogVOLE
statement includes this Volta-specific cross-setup binding.

### Gate screen

- **Proof.** Strict current headroom is `2,168,979 B`. Direct CI-VOLE removes
  at least the `6,609,600-B` Packed16 `d/e` payload. One reviewed LogVOLE ring
  digest is `225,280 B`; conservatively retaining every other current byte
  gives `61,446,700 B`. Even eight times that query traffic gives
  `63,023,660 B`. Proof size is the sole analytic PASS.
- **Setup.** The cap is `115,114,395 B`; after the C4 setup, a replacement has
  `76,742,930 B`. Reviewed semi-honest LogVOLE reports approximately `38 MB`.
  Its malicious no-golden variant is only estimated at `2--8x`. One hypothetical
  native-`Fp2` instance is approximately `114,371,465 B` at the low endpoint,
  leaving only `742,930 B`, and `342,371,465 B` at the high endpoint. Setup is
  OPEN, not a pass; setup NIZKs and stronger statistical parameters are not
  included in those reported bytes.
- **Field compatibility.** Concrete LogVOLE is over `Z_p`, while Volta needs
  `m = k + x Delta` for `Delta in Fp2`. Two independent `Z_p` instances do not
  by themselves bind the same maliciously chosen `x`. Even ignoring that
  consistency gap, the low malicious setup estimate is `190,371,465 B` and
  fails. Admission therefore requires one proved `Fp2`/rank-two instance with
  a single binding digest, not two unlinked base-field invocations.
- **Prover.** The absolute cap is `5.3359744321 s`; a C4-like replacement may
  spend at most `1.2313787151 s` above the `4.104595717-s` anchor. Scaling the
  paper's incompatible 16-core, 55-bit, semi-honest rate gives `0.325139845 s`
  for one padded vector, about `0.650279690 s` at the stated `2x` malicious
  endpoint and `2.601118760 s` at `8x`. These are projections on another
  machine and parameter set, not timing credit. The gate remains OPEN.
- **Verifier.** The ledger defines no numerical successor verifier gate. The
  accepted `3.322998133-s` C4.1 accounted time is used only as a provisional
  no-regression screen. CI-VOLE still creates a linear local key output; it
  does not directly return `K_q`. The verifier must stream or materialize and
  fold it. This gate remains OPEN until the owner sets a threshold and the full
  path is measured.
- **State and memory.** One padded `Fp2` output vector is `67,108,864 B` per
  party, far below the current `11,943,815,852-B` device headroom and suitable
  for streaming. The reviewed paper does not give exact retained sender secret
  state or malicious proof state for the required parameters, so the durable
  state gate remains OPEN.
- **Security.** A new statistical term must exceed
  `79.2198098700326` bits to keep the conservative union above 78. The paper's
  measured `sigma=40` yields only `39.999999999997` bits and FAILS. `sigma=80`
  would give `78.28514222152793`; the admission target is `sigma=96`, giving
  soundness `78.80928522995302` and weight privacy
  `95.99999991501639`, conditional on the malicious proof and existing
  assumptions.
- **No CRS.** A verifier-specific public key is allowed private preprocessing,
  not a common CRS. The malicious public-key construction nevertheless invokes
  FS lattice setup-certification NIZKs through `ZK.Setup` and gives no concrete
  proof or parameter bytes. It passes this gate only if those proof parameters
  are transparently and domain-separately derived in the ROM with no trapdoor,
  and the certified relation binds its `Delta` to the ordinary PCG connection.
  The paper's opened-setup alternative removes the NIZKs only by adding an
  online verifier reveal, so it belongs to interactive `C41SC1`.

### Generic constructions screened out

- Silent NISC and the 2011/2017 generic reductions retain garbled-circuit-scale
  work or setup. They supply syntax, not a C4.1 gate result.
- Authenticated garbling costs `256 B` per AND gate at `kappa=128`; the current
  proof headroom admits only `8,472` AND gates.
- Succinct HSS garbling is research-only and assumes an HSS-friendly PRG. Even
  its optimistic arithmetic rate of one `log p`-bit label per multiplication
  costs at least `24,883,200 B` for one multiplication per cell, or
  `66,355,200 B` at the static sparse census.
- Direct NIIP has a CRS and a raw `Fp2`-per-cell encoding alone is
  `49,766,400 B`. Succinct oblivious tensor evaluation is asymptotically
  attractive but explicitly uses a CRS and has no concrete Volta parameters.
- LogVOLE is the only communication-compatible primitive found. Its published
  measurements are semi-honest, `Z_p`, `sigma=40`; its malicious public-key
  extension has no implementation, exact bytes or compatible `Fp2` theorem.

### One-time and multi-response contract

Any future realization must bind `(connection, public-key digest, response
index, x_auth geometry)` into both the CI-VOLE and C41FS1 domains. Reserve and
durably burn the index before reading the proof; abort, crash and rejection
burn it, and selective retry is forbidden. LogVOLE's multi-identifier theorem
can support a connection-scoped reusable key only after the setup proof,
root-hiding loss and union over the admitted response cap are instantiated at
`sigma>=96`. No correlation output may be reused across identifiers.

## Result and exact resume conditions

Generic `C41NISC1` remains NO-GO. Name the sole research survivor
`C41FS-LV2`: C41FS1 for every public coin plus direct, malicious,
transparent, native-`Fp2` CI-VOLE authentication of `x_auth`.

Implementation remains stopped until a design supplies all of:

1. a proved single-digest `Fp2`/rank-two LogVOLE mapping;
2. transparent malicious setup certification, including the common-`Delta`
   relation to ordinary PCG, with exact bytes at `sigma>=96`;
3. exact provider/verifier algorithms, retained and peak state, and streaming
   output ownership;
4. analytic setup `<=76,742,930 B` and projected response work
   `<=1.2313787151 s` on the registered machine methodology;
5. an owner-set numerical verifier gate; and
6. owner GO for the narrow local implementation and its instrumented sparse
   census. Pod work remains separately prohibited.

## Literature ruling

- Boyle et al., *Efficient Two-Round OT Extension and Silent Non-Interactive
  Secure Computation*, [ePrint 2019/1159](https://eprint.iacr.org/2019/1159),
  gives no-trusted-setup silent preprocessing from base OT/PCG and the required
  masked-receiver-input syntax. General functions still reduce to garbled
  circuits; correlations are not free or reusable without a security proof.
- Ishai et al., *Efficient Non-Interactive Secure Computation*,
  [EUROCRYPT 2011](https://www.iacr.org/archive/eurocrypt2011/66320411/66320411.pdf),
  establishes general NISC from OT but explicitly pays per circuit gate and
  discusses bounded reuse/selective-failure issues.
- Mohassel--Rosulek, *Non-Interactive Secure 2PC in the Offline/Online and
  Batch Settings*, [ePrint 2017/125](https://eprint.iacr.org/2017/125), moves
  circuit-dependent work offline but retains garbled-circuit-scale setup.
- Couteau--Zarezadeh, *Non-Interactive Secure Computation of Inner-Product from
  LPN and LWE*, [ePrint 2023/072](https://eprint.iacr.org/2023/072), has linear
  encodings and defines its direct NIIP using a CRS; it is excluded here.
- Ng--Rindal--Shah, *LogVOLE: Succinct and Efficient Chosen-Input VOLE for ZK
  and Beyond*, [ePrint 2026/0925](https://eprint.iacr.org/2026/0925), gives the
  only reviewed polylogarithmic public-key query compatible with the response
  budget. Its concrete evaluation is semi-honest over `Z_p` at 40-bit
  statistical security; its malicious extension is unimplemented and invokes
  setup-certification NIZKs.
- Ishai--Li--Lin, *A Unified Framework for Succinct Garbling from HSS*,
  [ePrint 2025/442](https://eprint.iacr.org/2025/442), gives attractive
  communication asymptotics but its concrete arithmetic rate and assumptions
  fail the C4.1 fold screen.
- Dittmer et al., *Authenticated Garbling from Simple Correlations*,
  [ePrint 2022/836](https://eprint.iacr.org/2022/836), gives malicious NISC in
  an `F_OLE` hybrid with exact `16 kappa n + o(n)`-bit one-way communication;
  that permits too few AND gates here.
- Abram--Malavolta--Roy, *Succinct Oblivious Tensor Evaluation*,
  [ePrint 2025/336](https://eprint.iacr.org/2025/336), has polylogarithmic
  communication in the long tensor dimension but requires a CRS.
- Baum et al., *Mac'n'Cheese*,
  [ePrint 2020/1410](https://eprint.iacr.org/2020/1410), confirms that
  Fiat--Shamir can coexist with VOLE preprocessing for public-coin rounds. It
  does not turn a verifier-private challenge into a public Fiat--Shamir coin.
- Goldreich--Oren, *Definitions and Properties of Zero-Knowledge Proof
  Systems*, [Journal of Cryptology 7 (1994)](https://doi.org/10.1007/BF00195207),
  rules out treating a nontrivial plain-model one-message ZK proof as a free
  substitute for setup or interaction.
