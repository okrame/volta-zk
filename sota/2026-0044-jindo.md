## 1. Introduction

A zero-knowledge argument of knowledge (ZKAoK) is a cryptographic protocol that allows a prover to con- vince a verifier that it knows a secret witness for a given statement without revealing any information beyond the validity of the statement. It has become a core building block for various privacy-preserving protocols where se- lective disclosure of a client input to a server is required for authentication while preserving client privacy. Such examples include e-voting [ABGS23], anonymous creden- tials [BLNS23], secure aggregation [BGL + 23], and privacy- preserving signatures [AGJ + 24]. More recently, there has been growing demand for ZKAoKs in real-world applica- tions such as identity verification [Eur26, Nat26], digital

wallets [Eur24, KD25], and proof of humanity for AI secu- rity [Wor24]. In these protocols, the computational overhead for the client is primarily dominated by proof generation. Therefore, constructing efficient ZKAoK systems optimized for client-side proving scenarios is required to practically deploy these applications. In recent years, the paradigm for ZKAoK construction has rapidly evolved, driven by the polynomial interactive oracle proof (PIOP) framework [BFS20, CHM + 20], which provides a systematic and unified approach to designing ZKAoKs. In this framework, a proof system is first designed as an interactive oracle proof (IOP) [BSCS16], where in each round the prover sends oracles representing polyno- mials and the verifier responds with random challenges or evaluation queries to the polynomial oracles. Such an IOP is then compiled into a ZKAoK using a polynomial com- mitment scheme (PCS), a variant of a commitment scheme that enables efficient proof of evaluation of committed poly- nomials over finite fields. The key advantage of PIOP-based constructions is their broad support for various statements, ranging from general arithmetic circuits based on R1CS representations [CHM + 20] to lookup arguments [AST24] suitable for instruction set architectures. For a proof sys- tem constructed via PIOP compilation, the efficiency of the PCS used in the compilation determines the overall performance, including proof generation, verification, and proof size. Therefore, the PIOP framework reduces the construction of efficient ZKAoK systems to the construction of an efficient PCS, making PCS design a major research focus for improving the overall performance of PIOP-based ZKAoKs. To construct efficient PCSs, various designs have been proposed based on different cryptographic assumptions. PCSs were initially developed using pairing-based as- sumptions [KZG10, Lee21] or discrete logarithm-based as- sumptions [BBB + 18, WTS + 18], leveraging the algebraic structure of elliptic curves. Since these constructions do not provide post-quantum security, code-based construc- tions [GLS + 23, ZXZS20, GLH + 25, ACFY25] have been widely studied as an alternative, offering post-quantum security based on symmetric primitives. More recently, there has been growing interest in lattice-based construc- tions [CMNW24, NS24, HSS24, KLNO24, KLNO25], as they also offer post-quantum security. However, existing PCS designs primarily target blockchain applications such

as zkVMs and zkRollups [Eth, Pol], which prioritize small proof sizes and fast verification to address scalability issues in blockchain. Moreover, this design trend often overlooks proof generation speed and zero-knowledgeness, both of which are key requirements for client-side proving sce- narios. Therefore, designing PCSs tailored to client-side proving scenarios still requires further study [KB].

### 1.1. Our Contribution

In this work, we construct a new lattice based PCS, Jindo¹, optimized for client-side proving. We choose lattice cryptography because several recent constructions [HSS24, NS24, KLN + 26] exhibit faster proof generation than other approaches, which is the key priority in client-side proving. Specifically, we observe that the two recent constructions CELPC[HSS24] andGreyhound[NS24] have strong po- tential for client-side proving, but still have several limita- tions that hinder practical deployment. We therefore build a new lattice based PCS that addresses these limitations through the following contributions. **Flexible Parameters.**First, we design our PCS to support flexible parameter regimes so that it can be deployed in var- ious client-side proving scenarios. Specifically, we observe thatCELPCsupports this feature by introducing a novel encoding method tailored to the lattice setting. This allows a wide range of prime field sizes, from 128 to 1024 bits, which are particularly useful for proving statements about client- side ciphertexts or public keys in homomorphic encryption based protocols [HMSS25a, HMSS25b, HLSS25]. However, a key limitation ofCELPCis its large proof size, which stems from the structure of its polynomial evaluation proto- col. More precisely, its evaluation protocol supports only a polynomial sized challenge set, which requires several repetitions to attain negligible knowledge soundness error. In contrast, the evaluation protocol inGreyhoundsupports an exponentially large challenge set based on the analysis of [LS18], which eliminates the need for repetition. Fur- thermore, it allows composition with theLabrador[BS23] proof system to further reduce proof size. However, its limitation lies in its restricted parameter regime, where the commitment modulus must equal the coefficient modulus of the input polynomials and be congruent to5modulo8. This constraint prevents efficient polynomial multiplication via the number theoretic transform (NTT), which degrades overall performance. Thus,Greyhoundefficiently supports only small prime fields, such as 32-bit prime fields, making it difficult to deploy in more general settings. InJindo, we resolve these parameter-related issues by generalizing the evaluation protocol ofGreyhoundto sup- port aGreyhound-like extraction method while allowing a CELPC-like encoding method without imposing constraints on the commitment modulus. As a result, the evaluation protocol ofJindosupports flexible parameter regimes while offering a large challenge set, which avoids large proof

**Sublinear Masking.**Next, we design our PCS to achieve evaluation hiding with small computational overhead. Eval- uation hiding is crucial for achieving zero-knowledgeness in PIOP-based proof systems, but it often introduces non- trivial prover overhead. One way to measure this overhead is to compare the size of the additional masking values required for evaluation hiding with the input polynomial size*N*, as proposed in [CFW26]. For example, a com- mon approach to achieving evaluation hiding is to gen- erate commitments to masking values of size*N*and use them to hide the witness through batched evaluation, as in [BDFG21, GLH + 25, LZC + 26]. However, this approach generally requires*O*(*N*)masking overhead, which makes proof generation at least twice as slow. AlthoughCELPC andGreyhoundachieve sublinear masking overhead with- out using masking commitments, their techniques signifi- cantly degrade prover performance. More precisely,CELPC achieves evaluation hiding by randomizing the entire input witness itself, which does not generate masking commit- ments but incurs*O*(*N*)additional computational overhead. In contrast, evaluation hiding inGreyhoundrelies on the zero-knowledge version ofLabrador, which has no con- crete implementation, so its actual performance overhead is unknown. InJindo, we achieve evaluation hiding with sublinear masking overhead by generalizing the masking commitment technique. We observe that the overhead of masking com- mitments is amortized as the number of batched polynomials increases, since a single masking commitment can cover all of them. To exploit this property, we adapt the sub- polynomial evaluation structure of [LZC + 26], which was originally introduced for distributed SNARK generation. Specifically, our PCS first splits the input polynomial into *m*subpolynomials and generates a commitment for each subpolynomial. The evaluation protocol then reconstructs the evaluation of the input polynomial through batched evaluation of these subpolynomials. As a result, we reduce the masking overhead from*O*(*N*)to*O*(*N/m*), achieving sublinear masking overhead depending on the choice of*m*.

Through- out this section, we focus on the evaluation of multilinear polynomials over a prime fieldZ*p*for simplicity. The more general setting, which includes support for extension fields, is presented in Section 4.

### 5.1. Parameter Settings and Optimizations

We present the parameter settings and optimization tech- niques used in our implementation. We also provide a script in our source code that automatically selects the best performing parameters for a given coefficient spaceFand polynomial size*N*. **MSIS and MLWE.**For the hardness of the MSIS problem, we use Eq. (2) with root Hermite factor*δ≈.*005, following prior works [HSS24, ENS20, LNS20]. For the hardness

of the MLWE problem, we use the estimation algorithm of [APS15]. Based on these analyses, all MSIS and MLWE parameters are configured to provide 128-bit security. **Encoding.**For the encoding method, we implement the coefficient encoding*φ*Coefffrom Lemma 5. For the param- eter settings, we found that setting*b*around 32-bit yields favorable performance in terms of both proof size and proof generation speed. **Challenge Set.**For the challenge set*C*, we use the set*Sω* and analyze its spreadness over*Rp*based on Lemma 3. However, directly computing Eq. (1) in Lemma 3 requires *O*(*p*)time, which is infeasible when*p*is exponential in the security parameter. We therefore use the heuristic anal- ysis presented in [ESZ22], following prior works [ESZ22, + AAB 24, GLLO26, LNPS21] that also rely on the spread- ness of the set*Sω*. Based on this analysis, we use the minimum value of*w*that provides*η≈*2 *−*128 for the given coefficient modulus*p*and ring degree*d*. **Rejection Sampling with Rounded Gaussian.**To reduce sampling overhead, we use the rounded Gaussian distri- bution instead of the discrete Gaussian distribution, which is much faster to sample. We specifically observe that the statistical distance between the rounded Gaussian distribu- tion *−* and 2 the discrete Gaussian distribution is bounded by *O*(*σ*), where*σ* 50 is the standard deviation. In our parameter setting,*σ≈*2, which yields statistical distance about 2 *−*100 between the discrete Gaussian distribution and the rounded Gaussian distribution. Therefore, in our implemen- tation, we use the rounded Gaussian distribution to improve proving performance, while lowering the statistical security of evaluation hiding to 100-bit, which still provides strong practical security. We present a more detailed analysis in Theorem 9. **Optimization for Polynomial Arithmetic.**We use SIMD instructions, such as AVX512-IFMA, to accelerate polyno- *q*=Z*q*[*X*]*/*(*Xqo*= Z [*X*]*/*(*X* + 1), following [NS24, BKS 21]. Beyond *o* SIMD acceleration, we choose NTT-friendly moduli for both*q*and*q*, namely moduli satisfying2*d|q−*1and 2*d|q −*1, which enable fast polynomial multiplication via the number theoretic transform (NTT). We note that some lattice-based proof systems, such asLazer[LSS24], Labrador[BS23], andGreyhound[NS24], do not support such moduli because of constraints from knowledge extrac- tion, which introduces additional overhead.
