## Fixed flow and artifacts

Debian owns `verifier.bundle`, `verifier-lot.bin`, `model-setup.bin`, the setup
manifest and both durable burn stores. The `99,532,800-B` typed-key payload in
`verifier-lot.bin` never leaves Debian. Only the one-use `provider.bundle`
crosses to A100.

The producer runs C41FS1 until all 640 bridge corrections and 8,294,400 sparse
descriptor entries are fixed. It then creates `secret-request.bin` (330 B) and
waits. Debian validates that request against `verifier.bundle`, samples one
uniform `Fp2`, durably writes a 90-B response record, and exports the same
response once. The pod receives the response by an atomic final rename, folds,
closes and emits the proof plus the public request. The response itself remains
in Debian's durable store. All later coins are C41FS1-derived after absorbing
the private response.

Use only the owner-approved authenticated HTTPS artifact service with fresh,
single-use, short-expiry PUT/GET URLs. Never place URLs, credentials or bearer
tokens in Git, shell history, process arguments, logs or JSON. Lengths and
BLAKE3 digests travel over the authenticated control channel. Repository sync
is GitHub HTTPS only; no `gh`, Git-over-SSH, SCP/rsync or repository archive.
