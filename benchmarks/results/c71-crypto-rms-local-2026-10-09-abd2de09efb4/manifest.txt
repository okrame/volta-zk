Implementation and protocol parity
----------------------------------
RequiredGeometry owns only sorted exact keys (columns,[ex,ew,ey],weighted)
and max dyadic layer widths. Its private fields cannot be populated by a
certificate. During Recipes admission it compiles one circuit at a time,
applies the former Recipes envelope plus the existing full GKR widths()
validator, merges max widths, then drops that circuit. No Circuit is stored.
Recipes::required calls rms_required_with_geometry. This repeats every
former prepare context guard using a helper shared with the original
prepare: actual cells/nonempty<=D29, norms1..421, exact parameters length,
actual auxiliary and weight layouts, one root each, nonzero quantization,
nonempty Gamma and valid Attempt. It reconstructs the exact sorted unique
key set and compares it directly with cached keys. No digest substitutes
for equality. It computes count using the actual current cell dimension
and repeats all statistic_statement.required() shape/context validations.
The full reservation, roots, row counts, assignments and FS are not cached.

prepare's existing first-occurrence keys/program ordering and per-norm
assignment are preserved. The sorted geometry order is used for the
commutative maximum width/count only and never for GKR bind serialization.
Actual prove/verify use the original full circuits and their original MACs.
No FS event, phase, random request, Gamma, PCG row, correlation reservation,
NoPeek/producer API, root or proof/transcript byte format changes.
Production fails closed when geometry is absent. Only the existing cfg(test)
capacity-only constructor intentionally leaves None and keeps the original
required oracle; it cannot select the production path.
