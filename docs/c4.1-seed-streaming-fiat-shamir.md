# C4.1 successor: seed-only streaming verifier and Fiat--Shamir

Status: owner-authorized local implementation. No provider or pod run is
authorized by this document. The immutable C4.1 prover-time failure remains
controlling.

This design changes the verifier implementation and the public-coin
challenge derivation. It does not change the folded Packed16 identity, typed
setup, XOR4-MAJ7 predicate, proof relation, proof-size cap, degree-12 close,
PCS parameters, prover slab, setup traffic, or device-memory gates from
`c4.1-folded-query-high-degree-typed-ole.md`.

## Objective and terminology

The complete serialized prover artifact is the **proof**. **Verifier time**
for this experiment is

```text
read + deserialize + Fiat--Shamir replay + seed expansion + streamed fold
  + model checks + PCS + product/zero close + degree-12 close.
```

Network transfer is reported separately. The first empirical verifier-time
gate is deliberately open: a slow but resource-safe verifier runs to
completion and is recorded. Correctness, proof bytes, memory, one-time use,
soundness and weight-ZK remain binding.

## C41FS1 public transcript

The existing BLAKE3 Fiat--Shamir sampler is generalized by protocol profile;
the C6.2 constructor and byte behavior remain unchanged. C4.1 uses the
domain-separated profile `C41FS1`. Its nonzero public context binds:

- protocol, codec, security profile and exact geometry;
- model/setup/quantization and public-statement digests;
- connection binding and monotonically allocated response index;
- public incidence seed and typed-setup digest; and
- PCS parameter identity and the ordered proof-component census.

Every prover move before a challenge is bound as canonical bytes or as an
exact logical length plus a verifier-recomputed BLAKE3 digest. Length-only
events are rejected. Challenges are reconstructed and are not serialized.
Missing, repeated, reordered, truncated or noncanonical moves change all
later challenges or fail closed.

Fiat--Shamir replaces only public-coin challenges. Verifier-private `Delta`,
VOLE keys, seed keys, PCG allocation state and lot-burn state remain outside
the public transcript. Provider hiding entropy remains independent OS
entropy. The setup may remain interactive and precedes the one-message proof.

The fail-closed implementation cap is 131,072 challenges, four rejection
draws per field limb and 1,048,576 worst-case random-oracle limb queries. The
cap is an admission bound, not an exact census; the local full-schedule run
must record the exact C4.1 count before pod authorization.

## Soundness and weight privacy

The previous conditional terms remain:

- C4 anchor soundness `78.80929487391641` bits;
- five-response bridge batch `105.74650333511666` bits;
- close/setup root term `122.04580368894132` bits; and
- XOR4-MAJ7 multi-instance weight-ZK `120.0170064253057` bits under the
  owner-admitted `XOR4-MAJ7-128` assumption.

For Goldilocks rejection probability below `2^-32` per draw, exhausting four
draws is below `2^-128` per limb. Union over the registered 1,048,576 limb
queries is below `2^-108`. BLAKE3 collision/programming and state-restoration
are explicit computational bad events, not silently counted as field error.
The existing C6.2 theorem can be reused only as a pattern: C4.1 requires its
own composition boundary covering the model proof, bridge, PCS,
product/zero closure and degree-12 close. Numerical protocol credit requires
the complete conditional composition to remain above 78 bits and weight-ZK
above 78 bits. Failure is a hard stop before A100.

## Seed-only verifier state

The durable verifier inventory contains the authenticated XOR4-MAJ7 seed
keys, public incidence seed, external `Delta`, setup/connection bindings and
the next response index. For the current five-response inventory, the seed
keys occupy approximately `259,072 * 16 = 4,145,152 B`. It stores neither the
`99,532,912-B` expanded verifier lot nor a dense query.

For one response the verifier:

1. validates proof geometry and reserves the next one-time index;
2. records compact descriptors for matrix and cache bridge queries;
3. derives the post-correction bridge challenge through C41FS1;
4. walks the `3,110,400` cells in bounded chunks;
5. builds only the current query chunk from the descriptors;
6. expands the 17 required PRG outputs per cell from seed keys;
7. immediately accumulates typed `a`, signed `b`, and public correction
   folds; and
8. discards the chunk before the existing degree-12 close.

No full `a_keys`, `b_keys`, query, per-worker query or bridge-entry vector is
permitted on the streaming path. The materialized implementation remains
only as a small-geometry differential oracle.

The default chunk is 4,096 cells and is the sole calibration knob. Reduction
must be field-exact and independent of thread count.

## One-time state

An index is reserved and durably burned before verification can accept. A
malformed proof, verification failure or crash after reservation does not
make the index reusable. The local implementation reuses the existing
`ResponseAuthorizationStore`: atomic `create_new` plus file/directory sync
rejects duplicate and concurrent reservations. Gap-free index allocation and
rollback detection require durable non-rollback storage or an external
monotonic authorization service; ordinary local files cannot prove either
property after a storage snapshot is restored. This remains a deployment
preflight condition, not local cryptographic credit.

Re-expanding an already consumed interval is allowed only in an explicit
benchmark-replay mode that cannot commit acceptance state. Such samples are
diagnostic and never represent additional responses.

## Debian verifier and SIMD

The verifier-only path is CPU-only and must fail if CUDA is requested or
silently selected. On the current AArch64 Debian VM it runs release code with
`target-cpu=native`, at most four Rayon workers and bounded buffers. Scalar
loops remain the correctness reference. Assembly inspection must demonstrate
ASIMD/NEON in the hot loops; if LLVM does not vectorize a measured hot loop,
only that loop may gain a narrow `std::arch::aarch64` implementation with a
bit-exact scalar differential. No new SIMD dependency is admitted.

The process safety ceiling is 2 GiB peak RSS. The implementation target is
below 512 MiB. Crossing 2 GiB is a resource stop, not a verifier-time verdict.

## Local gates before any pod

Required local evidence:

1. C41FS1 prover/verifier parity and canonical transcript mutation tests;
2. materialized-versus-streaming equality on reduced geometries;
3. honest acceptance and tamper/reuse rejection;
4. exact results with one and four workers;
5. full-geometry seed-expansion timing and peak RSS on the Debian VM;
6. assembly evidence for the measured SIMD hot path;
7. complete soundness/weight-ZK composition above 78 bits; and
8. a verifier-only artifact reader with bounded canonical decoding.

The local timing report records proof I/O, decoding, C41FS1, descriptors,
incidence/PRG expansion, streamed folds, PCS, both closes, core time, total
time, RSS, faults, thread count and hardware metadata. It also measures the
C4 anchor on the same machine. No verifier-time ratio passes or fails this
first experiment.

## Future A100-to-client run

After all local gates, a separate ledger entry and owner GO must authorize a
single fresh A100 run. Repository synchronization uses GitHub HTTPS. The
party-separated prover bundle and public proof use an explicitly approved
authenticated HTTPS artifact channel with expected length and BLAKE3 digest;
Git, SCP, rsync, repository archives and exported long-lived credentials are
forbidden. The verifier secret never leaves the Debian VM.

The run must continue through local accept/reject even when prover or
verifier timing misses. It records new append-only A100 and Debian JSON files
at one clean SHA. C4.1 remains rejected unless a separate design also repairs
the immutable `1.935020839958646x` prover-time failure without spending proof
bytes, communication, security or memory.

## Rejection and cleanup

Reject this successor if it changes the relation, emits `>=70,000,000` proof
bytes, materializes a full verifier lot/query, permits lot reuse, uses mock
PCG for credit, falls below either 78-bit security gate, or requires more
than 2 GiB verifier RSS. Before a milestone checkpoint run the narrow tests,
then the Rust workspace and Lean when resources permit. Use only the
canonical `rust/target` and remove it after the checkpoint.
